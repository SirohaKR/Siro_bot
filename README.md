# 시로냥 — 메이플스토리 길드 관리 봇

역할 지정(캐릭터 인증/직급)과 채널 관리를 담당하는 디스코드 봇입니다.
파이썬을 잘 몰라도 따라할 수 있도록 설치부터 실행까지 순서대로 정리했습니다.

**설정은 명령어가 아니라 브라우저로 여는 "설정 페이지"에서 합니다.** 페이지에서
채널·역할을 고르고 버튼을 누르면, 봇이 알아서 공지 채널에 메시지를 올리거나
음성채널을 만듭니다. 실제로 항상 켜져 있어야 하는 프로그램은 두 개입니다.

- `main.py` — 디스코드에 접속해서 버튼 클릭/이미지 업로드/음성채널 입장을 실시간으로
  감시하는 "본체"
- `web/app.py` — 브라우저로 여는 설정 페이지 (설정할 때만 잠깐 켜도 되고, 계속 켜둬도 됨)

## 1. 폴더 구조

```
discordBot_시로냥/
├── main.py                ← 봇 본체 실행 파일. "python main.py"
├── CHANGELOG.md            ← 업데이트 내역. 맨 위에 새 "## 날짜" 항목을 추가해두면
│                             다음 재시작 때 "업데이트 로그" 채널에 자동으로 안내됨
├── requirements.txt        ← 필요한 파이썬 라이브러리 목록
├── .env.example            ← 토큰 등 비밀값을 넣는 양식 (복사해서 .env로 만들어 사용)
├── cogs/                   ← 기능별로 나눠놓은 폴더 ("Cog" = 기능 서랍 하나)
│   ├── verification.py     ← 입장안내 버튼 → 비공개 인증 스레드 → 관리자 승인/거절로 역할 부여
│   ├── roles.py            ← 공지 메시지의 이모지 반응을 감시해서 직업 등 역할을 셀프 부여/회수
│   ├── channels.py         ← 음성 허브 채널 입장을 감시해서 개인/자유 음성채널 자동 생성/삭제
│   ├── tts.py              ← 지정한 텍스트채널의 글을 음성채널에서 읽어주는 TTS
│   └── big_emoji.py        ← 이모티콘 하나만 온 메시지를 스티커 크기로 키워서 재게시
├── core/
│   ├── settings_store.py  ← 서버별 설정(어떤 역할/채널을 쓰는지)을 data/settings.json에 저장
│   ├── discord_api.py     ← 설정 페이지가 디스코드에 직접 요청을 보낼 때 쓰는 코드
│   └── changelog.py       ← CHANGELOG.md의 최신 항목을 읽어오는 코드
├── img/                    ← 공지/안내에 바로 골라 쓸 수 있는 내장 이미지 (설정 페이지의 "내장 이미지" 탭)
├── web/
│   ├── app.py              ← 설정 페이지 실행 파일. "python web/app.py"
│   └── templates/          ← 설정 페이지의 화면(HTML, 항목별로 페이지가 나뉨)
└── data/                   ← 처음 실행하면 자동으로 생기는 폴더. settings.json 저장됨
```

기능을 하나 더 추가하고 싶어지면, `cogs/` 안에 파일을 하나 더 만들고
`main.py`의 `INITIAL_EXTENSIONS` 목록에 이름만 추가하면 됩니다.

**업데이트할 때마다 하면 좋은 습관**: `CHANGELOG.md` 맨 위에 `## 2026-01-01`처럼 날짜
항목을 추가하고 바뀐 내용을 몇 줄 적어두세요. 대시보드에서 "업데이트 로그" 채널을
지정해뒀다면, 다음에 봇이 재시작될 때 그 내용을 자동으로 올려줍니다.

## 2. 준비물

- Python 3.10 이상 ([python.org](https://www.python.org/downloads/)에서 설치, 설치 시 "Add python.exe to PATH" 체크)
- 디스코드 계정 + 봇을 초대할 서버(길드 서버)의 관리자 권한

## 3. 디스코드 봇 만들고 토큰 발급받기

1. [Discord Developer Portal](https://discord.com/developers/applications) 접속 → 로그인
2. **New Application** 클릭 → 이름은 아무거나 (예: 시로냥) → Create
3. 왼쪽 메뉴 **Bot** 클릭 → **Reset Token**(또는 처음이면 바로 토큰 발급) → 나오는 토큰을 복사
   - 이 토큰은 비밀번호와 같습니다. 절대 남에게 보여주거나 깃허브에 올리지 마세요.
4. 같은 Bot 페이지에서 **Privileged Gateway Intents** 항목을 찾아 아래 두 개를 켜세요(ON).
   - **SERVER MEMBERS INTENT** — 역할을 부여/제거하려면 필요
   - **MESSAGE CONTENT INTENT** — 캐릭터 인증 스레드에 올라온 이미지 첨부파일을 읽으려면 필요

## 4. 봇을 서버에 초대하기

1. 왼쪽 메뉴 **OAuth2 → URL Generator**로 이동
2. **SCOPES**에서 `bot`과 `applications.commands` 둘 다 체크
   (`applications.commands`가 빠지면 `/설정` 같은 슬래시 명령어가 그 서버에 영원히 동기화되지 않습니다)
3. **BOT PERMISSIONS**에서 아래 권한 체크
   - Manage Roles (역할 관리) — 인증 승인 시 역할 부여, 직업/직급 역할 부여
   - Manage Channels (채널 관리) — 파티모집 개인 채널 생성/삭제
   - Move Members (음성채널 이동) — 허브 채널 입장 시 개인 채널로 이동
   - Create Private Threads, Send Messages in Threads — 캐릭터 인증용 비공개 채널 생성/대화
   - Add Reactions — 역할 선택 공지에 이모지를 미리 붙여두기 위해 필요
   - Manage Messages (메시지 관리) — 한 사람이 역할 선택 이모지를 여러 개 눌렀을 때 나머지를 정리,
     이모티콘을 크게 키워 다시 올린 뒤 원본 메시지를 지울 때도 필요
   - Connect, Speak (음성채널 연결/말하기) — TTS 기능이 음성채널에 들어가 소리를 내려면 필요
   - View Channels, Send Messages, Embed Links, Attach Files
4. 맨 아래 생성된 URL을 복사해서 브라우저 주소창에 붙여넣고, 봇을 넣을 서버를 선택해 초대

⚠️ **중요**: 초대 후 서버 설정 → 역할(Roles) 메뉴에서, 봇의 역할을 봇이 부여해야 하는
역할들(인증 역할, 직급 역할)보다 **위쪽**으로 옮겨주세요. 디스코드는 자기보다 낮은 순서의
역할만 부여/제거할 수 있어서, 순서가 안 맞으면 "역할 부여 실패" 오류가 납니다.

## 5. 설치 및 실행

프로젝트 폴더(`discordBot_시로냥`)에서 터미널(명령 프롬프트/PowerShell)을 열고:

```bash
pip install -r requirements.txt
```

`.env.example` 파일을 복사해서 이름을 `.env`로 바꾸고, 안에 있는 값들을 채웁니다.
- `DISCORD_TOKEN` → 3단계에서 복사한 토큰
- `WEB_ADMIN_TOKEN` → 설정 페이지 접속용 비밀번호 역할. 아무 문자열이나 길게 지어서 입력
- `FLASK_SECRET_KEY` → 아무 문자열이나 (세션 암호화용)

그다음 **터미널 두 개**를 열어서 각각 실행합니다 (하나는 봇 본체, 하나는 설정 페이지).

```bash
python main.py
```

```bash
python web/app.py
```

`main.py` 콘솔에 `✅ 시로냥 봇 실행/연결 완료`가 뜨면 봇 본체는 성공.
`web/app.py` 콘솔에는 실행 중인 주소가 표시됩니다. 종료할 때는 각 터미널에서 `Ctrl + C`.

## 6. 설정 페이지 사용법

먼저 서버에서 사용할 역할(전사/마법사/... , 길드마스터/부길드장/...)과 음성채널을
디스코드에서 미리 만들어두세요. 설정 페이지는 "이미 있는 역할·채널을 연결"하는 방식으로
동작합니다 (음성채널은 페이지에서 바로 새로 만들 수도 있습니다).

1. 브라우저에서 `http://localhost:5000/` 접속하면 로그인 화면이 뜹니다.
   비밀번호(`.env`의 `WEB_ADMIN_TOKEN` 값)를 입력하면 들어가집니다.
   (봇을 PC가 아니라 서버에 올렸다면 `localhost` 대신 그 서버 주소를 사용)
   또는 디스코드에서 **`/설정`** 명령어를 치면 이 주소를 봇이 대신 알려줍니다
   (`.env`의 `WEB_PUBLIC_URL`을 채워둬야 동작하고, 이 명령어는 "역할 관리" 권한이
   있는 사람에게만 보이는 답장으로 옵니다)
2. 서버가 여러 개면 목록에서 설정할 서버를 선택
3. 들어가면 **대시보드**가 뜨는데, 항목별 설정 여부를 한눈에 보여줍니다. 각 카드를
   누르면 해당 항목의 전용 페이지로 이동합니다 (왼쪽 사이드바로도 바로 이동 가능).
   페이지마다 입력값을 다 채우고 맨 아래 버튼 한 번만 누르면 저장/게시까지 끝납니다.
   - **🚪 입장 안내** — 안내 제목/내용(+이미지 선택)을 쓰고 올릴 채널을 골라서
     "입장 안내 게시하기".
     → 그 채널에 "🔑 캐릭터 인증하러 가기" 버튼이 달린 메시지가 올라갑니다.
   - **🔑 캐릭터 인증** — 인증 안내 제목/내용, 비공개 스레드를 만들 채널, 승인 시
     부여할 역할을 고르고 "캐릭터 인증 설정 저장".
     → 길드원이 위 버튼을 누르면 본인만 볼 수 있는 비공개 채널이 생기고 여기서 쓴 안내가
     표시됩니다. 이미지를 올리면 관리자에게 "✅ 승인 / ❌ 거절" 버튼이 뜨고, 승인하면
     역할이 자동으로 부여됩니다.
   - **🎭 역할 선택** — 공지 제목/내용을 쓰고 역할 이름+이모티콘+역할을 원하는 만큼
     "목록에 추가"로 쌓은 다음, 채널을 골라서 "공지 게시하기".
     → 그 채널에 메시지가 올라가고, 길드원이 이모티콘을 누르면 관리자 승인 없이 바로
     역할이 부여됩니다 (한 사람당 하나만 가지도록 자동 교체). 여러 개 중 하나를 셀프로
     고르는 용도라, 관리자 확인이 필요한 캐릭터 인증과는 다른 별도 기능입니다.
   - **📢 공지사항** — 이벤트, 소식처럼 그때그때 알릴 내용을 제목/내용(+이미지 선택)으로
     써서 원하는 채널에 게시. 누를 때마다 새 메시지로 올라갑니다.
   - **📜 길드 규칙** — 계속 채널에 남겨둘 규칙을 올립니다. 공지사항과 화면은 똑같지만
     따로 저장되고, 대시보드에도 따로 표시됩니다.
   - **🔊 음성 채널 자동 생성** — 허브(기존 채널을 고르거나 새로 만들기)를 원하는 만큼
     추가하고, 새로 생길 채널 이름 규칙을 정합니다 (`{user}`=입장한 사람 이름,
     `{n}`=순서 번호). 자주 쓰는 형태(이름별 파티방/1인 개인방/자유 음성방)는 버튼
     하나로 바로 채워집니다.
     → 그 허브 채널에 들어가면 정해둔 이름 규칙대로 새 채널이 자동 생성되고, 비면
     자동 삭제됩니다.
   - **🗣️ TTS** — 읽어줄 채널을 고르고 서버 기본 목소리를 선택 (목록의 "▶️ 미리듣기"를
     눌러서 브라우저에서 바로 들어볼 수 있음. 한국어 전용 목소리 외에 한국어를 읽을 수
     있는 "다국어" 목소리도 여러 개 들어있어 무료 목소리만 총 14종 중에 고를 수 있음.
     `.env`에 AWS 키를 넣어두면 유료인 AWS Polly의 "서연(Neural)" 목소리도 목록에
     추가로 나타남 — 아래 "AWS Polly로 더 좋은 음질 쓰기" 참고. `.env`에 타입캐스트
     키를 넣어두면 하준/박창수/발키리 등 캐릭터 목소리 600여종도 이름/성별/나이로
     검색해서 고를 수 있음 — 아래 "타입캐스트로 다양한 캐릭터 목소리 쓰기" 참고).
     읽기 전에 "ㅋㅋ", "ㅠㅠ", "ㄹㅇ", "ㅅㅂ" 같은 초성체/자모도 알아서 읽을 수 있는
     형태로 바꿔줍니다.
     → 그 채널에 글을 쓰면, 글쓴이가 지금 들어가있는 음성채널에서 봇이 소리로
     읽어줍니다 (카톡 채팅을 읽어주는 것과 같은 방식). 음성채널에 없을 때 쓴 글은
     무시됩니다. 길드원 각자가 디스코드에서 **`/목소리설정`** 명령어를 쓰면, 본인
     메시지만 따로 읽힐 목소리를 정할 수 있는 웹페이지 주소를 알려줍니다 — 아래
     "내 목소리 설정 페이지 켜기" 참고.

### AWS Polly로 더 좋은 음질 쓰기 (선택, 유료)

기본 목소리(edge-tts)는 무료지만, AWS Polly의 "Neural" 목소리를 쓰면 더 자연스러운
한국어 음성(서연)을 쓸 수 있습니다. 길드 사용량 정도면 보통 무료 한도 안에서 끝나요
(자세한 요금은 [AWS Polly 요금 페이지](https://aws.amazon.com/polly/pricing/) 참고).

1. [AWS 콘솔](https://aws.amazon.com)에서 계정 생성 (카드 등록 필요)
2. **IAM** → **사용자** → **사용자 생성** (이름은 아무거나, 콘솔 로그인 권한은 필요
   없고 "액세스 키 - 프로그래밍 방식 액세스"만 있으면 됨)
3. 권한 정책에서 **`AmazonPollyReadOnlyAccess`** 연결 (음성 합성에 필요한 만큼만)
4. 생성 완료 화면에서 나오는 **액세스 키 ID / 비밀 액세스 키**를 복사 (그 화면을
   벗어나면 다시 볼 수 없으니 바로 저장)
5. (추천) **결제 → Budgets**에서 소액 예산 알림을 만들어두면 예상 밖 과금을 바로 알 수 있음
6. `.env`에 아래 값을 채우기:
   ```
   AWS_ACCESS_KEY_ID=...
   AWS_SECRET_ACCESS_KEY=...
   AWS_REGION=ap-northeast-2
   ```
7. 봇 재시작 후 "🗣️ TTS" 페이지에 "서연 (여성, AWS Polly Neural · 유료)" 항목이 뜨면 성공.
   미리듣기도 그대로 됩니다.

AWS 키를 안 넣으면 이 항목은 그냥 안 보이고, 나머지 무료 목소리는 그대로 잘 동작합니다.

### 타입캐스트로 다양한 캐릭터 목소리 쓰기 (선택, 유료)

[타입캐스트(Typecast)](https://typecast.ai)는 하준/박창수/발키리 같은 캐릭터성 강한
한국어 목소리를 600종 넘게 제공하는 TTS 서비스입니다. AWS Polly보다 글자당 요금은
비싸지만(1,000자당 약 $0.07~0.075), 사투리·감정 표현이 있는 목소리를 쓸 수 있습니다.

1. [typecast.ai](https://typecast.ai)에서 회원가입
2. [API 문서](https://typecast.ai/docs/ko/quickstart)의 안내대로 API 키 발급
   (무료 플랜은 매달 15,000자 — 부족해지면 결제 플랜으로 업그레이드만 하면 되고
   코드는 그대로 씁니다)
3. `.env`에 채우기:
   ```
   TYPECAST_API_KEY=...
   ```
4. 봇/웹 재시작 후 "🗣️ TTS" 페이지에 하준/박창수 등 추천 목소리 7종과, 이름/성별/
   나이로 검색되는 전체 목소리 검색창이 뜨면 성공. 미리듣기는 타입캐스트가 미리
   준비해둔 무료 샘플을 쓰기 때문에 크레딧이 들지 않습니다 (실제로 메시지를
   읽을 때만 크레딧이 소모됩니다).

키를 안 넣으면 타입캐스트 관련 항목은 그냥 안 보이고, 나머지 목소리는 그대로 동작합니다.

### 내 목소리 설정 페이지 켜기 (선택 — 디스코드 로그인)

목소리 종류가 워낙 많아서(무료 14종 + 서연 + 타입캐스트 600여종) 디스코드
`/목소리설정` 명령어의 선택지(최대 25개)로는 다 담을 수 없습니다. 그래서 길드원이
직접 검색하면서 고를 수 있는 **오픈 웹페이지**(`/my-voice`)를 따로 만들었습니다.
관리자 페이지와 달리 비밀번호가 아니라 "디스코드로 로그인"으로 본인 확인을 하고,
로그인한 사람이 실제 길드 멤버일 때만 자기 목소리를 저장할 수 있습니다.

1. [디스코드 개발자 포털](https://discord.com/developers/applications)에서 봇
   애플리케이션 선택 → **OAuth2** 탭
2. **Redirects**에 아래 주소 추가 (WEB_PUBLIC_URL 뒤에 `/oauth/callback`만 붙이면 됨):
   ```
   http://exdrone.synology.me:5051/oauth/callback
   ```
3. 같은 화면에 있는 **Client ID**, **Client Secret**을 `.env`에 채우기:
   ```
   DISCORD_CLIENT_ID=...
   DISCORD_CLIENT_SECRET=...
   ```
4. `.env`의 `MY_GUILD_ID`도 채워져 있는지 확인 (이 값으로 "어느 서버 기준인지" 판단함)
5. 봇/웹 재시작 후, 디스코드에서 `/목소리설정` 명령어를 치면 이 페이지 주소를 알려줍니다.

이 값들을 안 넣으면 로그인이 실패하지만, 관리자 페이지나 다른 기능에는 영향이 없습니다.

   - **👑 길드 직급** — 길드마스터/부길드장/길드원/신입길드원에 서버 역할을 연결.
   - **🧑‍🤝‍🧑 역할 부여** — 멤버와 직급을 골라서 관리자가 직접 부여 (셀프 지급 아님).
   - **🧹 채팅 정리** — 채널을 고르고 한꺼번에 메시지를 지워서 깨끗하게 정리. **지운
     메시지는 복구할 수 없어서**, 실행 전에 "동의합니다" 체크박스를 직접 체크해야만
     버튼이 활성화됩니다(채널을 바꾸면 체크가 풀려서 다시 확인함). 14일 이내
     메시지는 빠르게 지워지지만, 그보다 오래된 메시지는
     디스코드 자체 제한으로 하나씩 지워야 해서 개수가 많으면 시간이 걸립니다.

대시보드 맨 아래 **🔔 업데이트 로그** 항목에서 채널을 지정해두면, 코드가 업데이트될
때마다(`CHANGELOG.md`에 새 항목이 추가되고 봇이 재시작되면) 바뀐 내용을 그 채널에
자동으로 올려줍니다.

글 내용을 쓰는 칸 위에는 **글쓰기 툴바**(H1/H2/H3/B/I/U/S/인용/목록/코드/링크)가 있어서,
마크다운 문법을 직접 안 외워도 원하는 글자를 선택하고 버튼만 누르면 꾸며집니다. 오른쪽
미리보기에도 실제 디스코드처럼 그 서식이 바로 반영돼요.

값을 바꾸고 싶으면 언제든 해당 페이지에서 다시 설정하면 됩니다 (덮어쓰기 방식).

**설정 페이지 없이 항상 켜져 있는 기능도 있습니다**: 누군가 이모티콘 하나만 딱 채팅에
올리면(다른 글자 없이), 봇이 그 이모티콘을 스티커만큼 큰 이미지로 새로 올리고 원본
메시지는 지웁니다 (`cogs/big_emoji.py`, 봇에게 '메시지 관리' 권한이 없으면 원본은
못 지우고 큰 이미지만 새로 올라갑니다). 모든 채널에서 자동으로 동작해요.

## 7. 나스(Docker)에서 다른 봇과 같이 돌리기

이미 나스에서 돌리고 있는 다른 봇(예: UtaHime)이 있어도, **포트만 겹치지 않게 하면**
같은 나스에서 문제없이 같이 돌릴 수 있습니다. `main.py`(봇 본체)는 디스코드로 나가는
연결만 하기 때문에 포트나 URL이 아예 필요 없고, 포트가 필요한 건 브라우저로 여는
`web/app.py`(설정 페이지) 하나뿐입니다.

이 폴더에는 UtaHime와 동일한 방식의 `Dockerfile`, `docker-compose.yml`이 이미 있습니다.

```bash
docker compose up -d --build
```

이렇게 하면 컨테이너 두 개가 뜹니다.
- `sironyan-bot` — 포트 필요 없음 (봇 본체)
- `sironyan-web` — 나스의 **5051번 포트**를 컨테이너 내부 5000번에 연결해서 엽니다
  (`docker-compose.yml`의 `"5051:5000"` 부분. UtaHime가 이미 5050을 쓰고 있다면 겹치지
  않는 다른 숫자로 왼쪽 값만 바꾸면 됩니다)

그 다음 나스의 리버스 프록시(시놀로지면 제어판 → 로그인 포털 → 고급 → 역방향 프록시,
DSM 버전에 따라 위치가 다를 수 있음)에서 원하는 URL(예: `sironyan.내도메인.com`)을
`localhost:5051`로 연결해주면, UtaHime는 그대로 두고 시로냥만 새 주소로 열립니다.
**즉 말씀하신 대로 URL(포트)만 다르게 잡아주면 됩니다.**

설정 페이지 접속 주소는 `https://sironyan.내도메인.com/` (또는 직접 포트로 열었다면
`http://나스주소:5051/`) 형태가 되고, 들어가면 로그인 화면에서 `WEB_ADMIN_TOKEN` 값을
비밀번호로 입력하면 됩니다.

컨테이너 안에서도 데이터(어떤 역할/채널을 쓰는지)가 사라지지 않도록, `data/` 폴더를
호스트와 공유하도록(`volumes`) 이미 설정해뒀습니다.

## 8. 자주 겪는 문제

- **`/설정` 등 슬래시 명령어가 서버에 안 뜨거나 동기화가 안 돼요** → 4단계에서 봇을 초대할 때
  OAuth2 SCOPES에 `applications.commands`를 빼먹었을 가능성이 큽니다. Developer Portal에서
  URL Generator로 `bot` + `applications.commands`를 함께 체크해서 새 URL을 만든 다음, 봇을
  빼지 않고 같은 서버로 다시 초대(재인증)하면 스코프가 추가됩니다.
- **로그인 화면에서 비밀번호가 계속 틀렸다고 떠요** → `.env`의 `WEB_ADMIN_TOKEN` 값과
  정확히 같은지 확인하세요 (대소문자/공백 포함).
- **역할/멤버 목록이 비어 보여요** → 3단계의 SERVER MEMBERS INTENT를 켰는지 확인하고,
  `.env`의 `DISCORD_TOKEN`이 올바른지 확인하세요.
- **"역할 부여 실패" 계열 오류가 나요** → 4단계의 ⚠️ 안내처럼 봇의 역할 순서를 부여하려는
  역할보다 위로 올려주세요. 디스코드는 자기보다 낮은 순서의 역할만 부여/제거할 수 있습니다.
- **버튼을 눌러도 반응이 없거나, 이미지를 올려도 승인 카드가 안 떠요** → `main.py`(봇 본체)가
  켜져 있는지 확인하세요. 설정 페이지(`web/app.py`)는 안내 메시지를 "올리는" 역할만 하고,
  버튼 클릭/이미지 감지는 `main.py`가 합니다. 이미지가 안 뜬다면 3단계의
  MESSAGE CONTENT INTENT를 켰는지도 확인하세요.
- **역할 선택 이모티콘을 눌러도 역할이 안 붙어요** → 이것도 마찬가지로 `main.py`가 켜져
  있어야 합니다. 그래도 안 되면 봇에게 Add Reactions 권한이 있는지, 4단계 ⚠️ 안내처럼
  역할 순서가 맞는지 확인하세요.
- **봇이 오프라인으로 보여요** → `python main.py`를 실행한 터미널 창을 닫으면 봇도 꺼집니다.
  계속 켜두려면 터미널을 그대로 두거나, PC를 껐다 켜도 계속 돌게 하려면 별도의 서버(VPS)나
  Docker 배포가 필요합니다 (필요하면 요청해주세요, 추가로 구성해드릴 수 있습니다).
